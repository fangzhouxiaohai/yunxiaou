# 云小U 前端整体 UI 美化设计

日期：2026-08-17
状态：已获用户批准
范围：方案 B —— 全局设计层 + 布局外壳重做 + 登录页重做 + 12 个业务页逐页精修 + 暗色模式切换 + 响应式/移动端适配 + 修改密码功能（默认账号 admin / 123456）

## 目标

当前前端为 Element Plus 默认风格，全局样式仅 3 行 reset，各页面为裸组件直接摆放。本次美化在**不改任何业务逻辑、接口调用、交互行为**的前提下，整体提升视觉品质，风格定位为「经典深色侧边栏管理台的现代化精修版」。

## 第 1 节：全局设计层（`apps/web/src/styles/index.scss` 扩展）

- 设计令牌：CSS 变量定义
  - 主色 `#3b6fe0`，成功/警告/危险语义色
  - 8 级灰阶
  - 圆角：卡片 8px、控件 6px
  - 三级阴影（卡片、浮层、弹窗）
  - 间距刻度（4 的倍数）
- Element Plus 主题覆盖：通过 `--el-*` CSS 变量统一主色、圆角、边框色
  - 表格：头部浅灰底 `#f7f8fa`、行 hover 高亮、去除竖向边框
  - 按钮：去除默认粗描边观感
  - 对话框 / 抽屉 / 消息框：统一 8px 圆角
- 全局细节：细滚动条样式、文本选中色、数字等宽（`tabular-nums`，用于监控数值）、通用工具类（页面容器、卡片间距）
- 字体栈保留系统中文字体（PingFang SC / Microsoft YaHei）

## 第 2 节：布局外壳（`apps/web/src/layout/index.vue`）

- 侧边栏：
  - 背景 `#0f1f3d` 深蓝微渐变
  - logo 区加底部分隔线，字号字重优化
  - 菜单项：高度 44px、左右内边距 16px、图标与文字间距统一
  - 选中项：圆角色块 + 左侧 3px 高亮条
  - hover 态柔和过渡
- 顶栏：
  - 白底 + 细投影（替代现有灰边线）
  - 左侧页面标题加大至 17px
  - 右侧服务器选择器与用户信息之间加竖分隔线
  - 用户区 hover 变色
- 内容区：背景 `#f5f7fa`，统一 16px 内边距

## 第 3 节：登录页（`apps/web/src/views/login/index.vue`）

- 背景：深蓝渐变 + 细微网格/光晕纹理（纯 CSS，不引入图片资源）
- 卡片：440px 宽、12px 圆角、大投影
- 顶部品牌区：产品名 + 一句话副标题
- 输入框：大号、前置图标
- 登录按钮：全宽、大号
- 进入动画：淡入上移

## 第 4 节：业务页逐页精修（12 个页面）

只调整结构、间距、组件用法，不动业务逻辑。

- **监控大盘**：4 个统计卡升级为带图标和趋势色的指标卡；图表卡片统一标题栏样式；系统信息描述表间距优化
- **服务器管理 / 计划任务 / SSL / 日志 / 磁盘 / 进程守护**：列表页统一为「页面头部（标题 + 主操作按钮）+ 卡片包裹表格」结构；表格操作列按钮改文字链接式；空状态居中
- **软件商店**：软件卡片栅格统一高度，图标区与操作区对齐；版本标签样式统一
- **数据库 / 项目 / 文件管理 / 终端**：结构复杂，只做间距、卡片包裹、按钮层级、对话框排版精修，不动交互结构

## 第 5 节：暗色模式切换

- 方案：Element Plus 官方暗色变量（`element-plus/theme-chalk/dark/css-vars.css`）+ `html.dark` 类切换；第 1 节的自定义设计令牌全部写成「亮/暗」两套（`:root` 与 `html.dark` 下各一份）
- 侧边栏在两种模式下都保持深色（运维工具惯例），内容区、顶栏、卡片、表格、对话框随模式切换
- 顶栏右侧加切换按钮（太阳/月亮图标），选择持久化到 `localStorage`；未选择过时跟随系统 `prefers-color-scheme`
- ECharts 图表（监控大盘）跟随模式：背景透明，坐标轴/文字颜色读取当前主题变量
- 登录页保持深色渐变背景，两种模式下观感一致

## 第 6 节：响应式 / 移动端适配

- 断点：`<768px` 手机、`<1024px` 平板、桌面为默认
- 侧边栏：手机/平板下收起为顶栏汉堡按钮 + 抽屉式菜单（overlay）；桌面保持固定侧边栏
- 顶栏：小屏下服务器选择器宽度收缩（min-width 0、可换行），用户名在手机下隐藏只留图标
- 栅格：监控大盘统计卡 `xs=24 sm=12 lg=6`，图表卡 `xs=24 lg=12`；其余页面的 el-row/el-col 同步补响应式 span
- 表格：保持 el-table 原生横向滚动；操作列按钮在小屏收起为下拉
- 对话框/抽屉：宽度统一改为 `min(Npx, 92vw)` 形式
- 登录卡片：`width: min(440px, 92vw)`
- 终端、文件管理等复杂页在移动端保证「可用」（不留白、不溢出），不做专门手机交互设计

## 第 7 节：修改密码功能

现状：账号密码来自 `.env`（`ADMIN_USER` / `ADMIN_PASSWORD`），登录时内存比对，无持久化，无法运行时修改。

设计：

- **默认凭据**：代码兜底默认值改为 `admin` / `123456`（`server/src/config.js`），`.env.example` 同步改为 `ADMIN_PASSWORD=123456`；`.env` 中已显式设置时仍以 `.env` 为准
- **持久化**：新增 `server/data/auth.json`（JsonStore 原子写入），存放 `{ username, passwordHash, salt }`，密码用 Node 内置 `crypto.scrypt` 加盐哈希，不存明文
- **凭据优先级**：`auth.json` 存在时以它为准；否则用 `.env` 配置；再否则用默认值 `admin / 123456`
- **新接口**：`PUT /api/auth/password`（需登录），入参 `{ oldPassword, newPassword }`；校验旧密码（timingSafeEqual 比对哈希）、新密码最少 6 位；成功后写入 `auth.json` 并记录审计日志
- **前端**：顶栏用户下拉新增「修改密码」项，弹出对话框（旧密码、新密码、确认密码）；`api/auth.ts` 增加 `changePassword`；成功提示后保持登录态（已签发的 JWT 24h 内仍有效，属可接受行为，写进 README 说明）
- **锁定策略**：修改密码接口复用登录失败计数，旧密码错误也计入，防止爆破

## 第 8 节：验证

- 每个阶段完成后 `cd apps/web && npm run build` 必须通过；后端改动后 `cd server && npm test` 必须通过（为修改密码接口补充测试用例）
- 全部完成后逐页面视觉走查（亮色/暗色两种模式、桌面/手机两种宽度）
- 回归约束：除修改密码功能外，不改任何接口调用、状态逻辑、交互行为

## 非目标（YAGNI）

- 不引入 Tailwind 或第三方主题包
- 不做多用户/角色体系（仍为单管理员）
- 不改动 SSH、终端、文件传输等后端核心逻辑
